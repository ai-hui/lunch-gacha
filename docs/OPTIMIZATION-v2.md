## 三、P0：修复「动画全没了」的回归（**最高优先级**）

### 症状
用户机器上 `Windows 动画效果 = 关闭`（注册表 `HKCU\Control Panel\Desktop\WindowMetrics\MinAnimate = 0`），
浏览器因此上报 `prefers-reduced-motion: reduce`。当前代码把这个系统偏好直接当成
「跳过全部演出」，导致**抽卡动画完全消失，点一下直接出结果**。

### 根因（当前代码）
- `index.html:783`：`REDUCE` 由 `matchMedia("(prefers-reduced-motion: reduce)")` 决定。
- `index.html:1565`：`if(!REDUCE){ ...播动画... }` —— `REDUCE` 为真时**整段演出被跳过**。
- `index.html:384-389`：CSS 媒体查询把 `.rcard`、`.reel .cur`、`.ring i`、
  `.cg-card.win`、`.rshine::before` 等**核心演出元素**的动画全部 `animation:none!important`。

### 设计原则（本轮最重要的一条）
> **抽卡演出是产品的核心内容，不是装饰。**
> 系统级的「减少动效」偏好只应该影响「背景装饰性动画」（网格流动、光晕漂浮这类无限循环），
> **绝不能**让用户失去抽卡过程本身。

### 改法

**1. 拆成两个独立开关，别混用一个 `REDUCE`**

| 开关 | 来源 | 作用范围 |
|---|---|---|
| `REDUCE_MOTION`（系统偏好，只读） | `matchMedia("(prefers-reduced-motion: reduce)")` | **仅**背景装饰：`.bg-grid`、`.orb-bg` 这类无限循环动画。**不得**影响任何抽卡演出 |
| `S.animStyle`（用户设置，持久化） | 页面上的新选择器 | 演出的呈现强度：`full`（完整）/ `lite`（精简版，时长缩短但保留过程）/ `off`（关闭） |

**2. `REDUCE` 改名 `REDUCE_MOTION`，且只用于背景**

- 删除 `if(!REDUCE){ ...演出... }` 这种「整个跳过」的写法。
- 演出**永远执行**，只由 `S.animStyle` 决定强度：
  - `full`：完整时长（当前行为）。
  - `lite`：时长按比例缩短（见下面的缩放表），但**动画过程一个不少**（光球照样汇聚、轮盘照样转、卡带照样滚）。
  - `off`：跳过演出，直接出结果（供明确不需要动画的用户手动选）。
- `REDUCE_MOTION` 为真时，只把 CSS 媒体查询的作用范围**收窄到背景装饰**，
  **必须移除** `.rcard` / `.rcard::before` / `.reel .cur` / `.ring i` / `.core.on` /
  `.speedlines` / `.shock.go` / `.rshine::before` / `.beams` / `.cg-card.win` /
  `.cg-card.win::after` / `.dish.c-UR` / `.rbadge.c-UR` / `.day.r-UR` / `.bar .bf`
  / `h1` / `.btn.primary` 这些**演出相关**选择器。
  保留：`* { transition-duration: .01ms !important }` 可以保留（只影响过渡，不影响关键帧动画），
  但 `animation:none` 必须只作用于背景装饰。

**3. 时长缩放表（`lite` 模式）**

用一个全局系数 `T` 控制各段时长，**不要散落一堆 if**：

| 段 | full | lite（建议系数） |
|---|---|---|
| `phaseSummon` 召唤 | 1250ms + 260ms | ×0.35 |
| `spinReel` 轮盘 | 2500ms | ×0.35 |
| `animCsgo` 滚动 | 5000ms | ×0.35 |
| `animCsgo` 定格停留 | 1500ms | ×0.4 |
| `reveal` 揭示停留 | R 1800 / SSR 2200 / UR 2600ms | ×0.4 |
| `reveal` 前的 160ms 间隔 | 160ms | ×0.4 |

实现方式：新增全局函数 `dur(ms)`，返回 `S.animStyle === "lite" ? Math.max(120, Math.round(ms * 0.35)) : ms`
（`reveal` 停留用 `0.4` 系数，所以 `dur` 接受第二个参数 `k`）。

**4. 新增用户可见的「演出强度」选择器**

在配置区「动画」那一段**下面**加一行新的选择器（不要塞进原来那三个按钮里）：

```
演出强度： [🎬 完整] [⚡ 精简] [⏭️ 关闭]
```

- 存到 `S.animStyle`，默认 `"full"`。
- 写进 `def`、localStorage 初始化校验、`exportObj()`（字段名 `animStyle`）、
  `importObj()`（校验 `"full"/"lite"/"off"`，非法值回落 `"full"`）。
- `data.json` 模板里**不要**加这个字段（保持 data.json 干净，由上级 Agent 决定要不要加）。

**5. 界面提示要说人话**

在 `#animStat` 那一行（或它下面）加一句状态说明，**让用户能一眼看出为什么没动画**：

- `animStyle === "off"` → 显示「当前已关闭演出动画，点击抽签会直接出结果」+ 提示怎么改回。
- 系统 `REDUCE_MOTION` 为真 → 提示「检测到系统开启了『减少动效』，背景动画已降级（不影响抽卡演出）」。
- 否则 → 不显示这段提示。

**6. 顺手修一个相关的小问题**

`renderAnimSeg()` 里 `#animStat` 的文案硬编码了「魔法阵 / CSGO 开箱」两套动画，
新增动画后必须改成**按 `ANIM_LIST` 动态生成**，否则会出现「加了动画但统计里没有」的不一致。

### P0 验收口径

1. **模拟 `prefers-reduced-motion: reduce`（Playwright `reduced_motion="reduce"`）**：
   - 抽签时**必须能看到动画过程**（轮盘在转 / 卡带在滚），
   - 结束后菜单出现结果，**不得**出现「一点直接出结果」。
   - 断言方式：抽签后立刻（动画进行中）检查 `.reel` 有 `.spinning` class，
     或 `#csgo` 有 `.on` class —— 二者至少命中一个。
2. **默认（无系统偏好）**：动画完整播放，行为与现在一致。
3. **`animStyle = "off"`**：直接出结果（这是用户主动选的，允许）。
4. **背景动画**：系统 reduce 时 `.bg-grid`/`.orb-bg` 的 `animation` 确实被关掉，
   但 `.rcard`/`.reel .cur` 的**没有**被关掉。
5. **localStorage 持久化**：`animStyle` 刷新后保持。
6. **导出/导入往返**：`animStyle` 正确带出带进。

## 四、P1：新增抽卡动画（用户明确要求「看有没有其他的抽奖动画可以加的」）

### 目标
在保留现有两套（魔法阵召唤 / CSGO 开箱）的基础上，**再新增 2 套**风格明显不同的演出，
并让它们进入「随机轮换」池。总数变成 4 套。

### 新增动画 A：🎰 赛博老虎机（`slot`）
- 复用现有的 `#reel` 舞台元素（不要新开 DOM），做成**三列**同时滚动的老虎机。
- 3 列各自独立滚动、错开停止时间，最后一列停下并对准结果。
- 停稳时列框发光 + 一次白闪 + 咔哒声收尾。
- 需要改 `#reel` 的 HTML 结构（现在是 `.prev / .cur / .next` 三个 div）。
  **改法**：保留 `.reel` 容器 id 不变，内部结构改成 3 个 `.slot-col`（每列一个 `.slot-item`），
  原来的 `.prev/.cur/.next` 结构**可以不再使用**（`setReel()` 一并改写）。
  注意：`spinReel()` 是魔法阵动画的一部分，**不要删**，改为魔法阵专用；
  新建 `animSlot()` 独立实现老虎机。
- 稀有度决定配色：UR 时边框金色流光。

### 新增动画 B：🎴 命运卡牌（`cards`）
- 一叠牌（3~5 张）背朝上，依次「翻牌」亮出，**最后一张是结果**（与 CSGO 的滚动不同，
  这套是「逐张翻」的节奏感）。
- 每翻一张：翻牌 3D 旋转（`rotateY` 180°）+ 音效 + 轻微粒子。
- 翻到结果牌时：牌面放大发光 + 白闪 + 冲击波环。
- 实现方式：新增一个覆盖在 `#stage` 上的容器（复用 `#csgo` 那套「独立层」思路，
  但**新写自己的 DOM**，id 例如 `#cards`），播完移除。
  不要复用 `#csgo` 的元素，否则两套动画会互相干扰。

### 通用要求（两套新动画都要满足）
- **不依赖 `REDUCE_MOTION`**：演出照播，只是时长随 `animStyle` 缩放。
- **异常安全**：内部任何一步抛错都不能阻断抽签（沿用现有 `try/catch` 思路）。
- **结束后清理**：移除临时 DOM、取消仍在运行的动画（不要留下持续耗电的合成层）。
- **音效**：复用现有 `tone()` / `noise()` / `sfxTick()`，不要新增音频文件。
- **粒子**：复用现有 `burst()`，粒子总数受现有上限约束。

### 动画注册（必须改的地方）
- `ANIM_LIST` 改成 4 个：`["gacha", "csgo", "slot", "cards"]`。
- `ANIM_NAME` 补两个新名字。
- `pickAnim()` 的加权逻辑**要适配 4 个动画**：现在是「间隔 gap 越大权重越高」，
  4 个动画时如果沿用 `1 + gap`，最久没出的那个会占绝对优势。
  **改法**：权重改为 `w = 1 + g`，但把 `g` 的封顶从 6 降到 4，
  并**保证每种动画的最低权重不低于 1** —— 让「随机」模式下四种动画都能轮到，
  而不是几乎只出最久没出现的那套。
  **同时要更新 `#animStat` 的说明文案**，如实写清新口径。
- `renderAnimSeg()`：改成**动态遍历 `ANIM_LIST`** 生成统计文字（不要硬编码）。
- **动画偏好选择器**：现有的 `[data-anim]` 按钮只有「随机/魔法阵/CSGO」三个，
  必须补上「🎰 赛博老虎机」「🎴 命运卡牌」两个按钮，
  并把 `.seg` 容器改成能自动换行（`flex-wrap`，已有则确认）。
- 旧的 `S.animLog` 只有 gacha/csgo 两个 key，新动画首次出场时自动新建，**不用管旧数据**。
- `S.animPref` 校验：新增两个值要加入白名单（`"random"/"gacha"/"csgo"/"slot"/"cards"`），
  导入时的校验同步。

### P1 验收口径
1. 4 套动画**逐个都能单独触发**（用 `[data-anim]` 按钮锁定后抽签），
   每次都能看到该套动画的过程，且结束后菜单出现正确结果。
2. 「随机」模式下连续抽 12 次，**4 套动画都至少出现过 1 次**（用 `S.animLog` 的 4 个 key 判定）。
3. 4 套动画在 `prefers-reduced-motion: reduce` 下**依然播放过程**（只是时长变短）。
4. 抽满一整周（5~6 天）**零 console error、零未捕获异常**。
5. `animStyle` 三档（full/lite/off）都能正常工作，且刷新后保持。
6. `#animStat` 的文案**包含全部 4 套动画**（断言文本里有 4 个名字）。
